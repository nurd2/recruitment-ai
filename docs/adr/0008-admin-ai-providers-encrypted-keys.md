# Admin-managed AI providers with credentials encrypted at rest

The AI provider set is expanded to five named choices — OpenAI, DeepSeek, Gemini, Anthropic, and Custom (any OpenAI-compatible endpoint) — and the admin UI lets an operator type an API key directly instead of only referencing an env var. Keys are AES-256-GCM encrypted with the server-side `APP_ENCRYPTION_KEY` before being stored in `ai_config.api_key_enc`; the plaintext is never persisted, audited, or returned to the browser, and the key is only decrypted at runtime by the server/worker. Each named provider ships a preset base URL and default model, while the Custom provider requires an explicit base URL. An optional, non-blocking "Test connection" action validates credentials with a cheap request. Legacy env-var-name references (`api_key_env`) remain honored when no encrypted key is present, so existing configs keep working. This balances the operator's need to configure credentials in-app with the requirement that a database leak does not expose usable keys.
