# Status colors stored as semantic keys per pipeline stage

Application Status badges are color-coded per stage. Each `job_title_status` row gains a `color` column holding one of eight stable semantic keys (`gray`, `blue`, `cyan`, `violet`, `amber`, `green`, `red`, `orange`) defined in `lib/status-colors.ts` — never raw hex or Tailwind classes. This keeps the palette theme-aware (light + dark), lets each Job Title customize its pipeline's colors independently (consistent with the existing per-job-title pipeline model), and makes future restyling a code change rather than a data migration. The default pipeline ships a curated mapping (Pending→gray, Screening→blue, Interview 1→cyan, Interview 2→violet, Offer→amber, Hired→green, Rejected→red) applied when a job title is created and backfilled to existing default statuses; new or custom statuses default to gray. Colors render wherever a status name appears — pipeline table, candidate detail, the status editor's swatch picker, and the change-status/filter dropdown dots — and are editable in the status editor via a new `setStatusColorAction`. A name-based fixed mapping was rejected because custom or renamed statuses would silently fall back to gray; raw hex was rejected because it cannot adapt to dark mode and offers no contrast guarantees. Color is a presentation attribute of a status, deliberately kept out of the domain glossary (`CONTEXT.md`).
